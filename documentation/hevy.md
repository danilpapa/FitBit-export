# Загрузка тренировок из Hevy

## Что делает

Если в заметке к тренировке в Google Health лежит только ссылка `https://hevy.com/workout/...`, команда `strength` открывает эту публичную страницу в невидимом Chrome, забирает текст подходов и подставляет его вместо ссылки. Дальше агент работает с обычным текстом, как будто ты вставил подходы руками.

Бесплатного API у Hevy нет: официальный API только для Hevy Pro. Поэтому мы читаем страницу так же, как её видит любой человек по ссылке.

## Как это работает

```text
заметка со ссылкой → есть ли уже подходы? → нет → Chrome открывает страницу
→ ждём, пока появятся подходы → берём текст → приводим к формату заметок → подставляем вместо ссылки
```

Код лежит в `internal/hevy/`: `hevy.go` отвечает за Chrome, `text.go` за разбор текста. Подключается в `internal/report/strength.go` (`readHevyPages`).

## Интересные моменты в коде

**Один Chrome на весь запуск.** Chrome запускается лениво, только при первой ссылке (`sync.Once`), а каждая страница открывается в своей вкладке. Это как один `WKProcessPool` на несколько `WKWebView`: запустить браузер дорого, открыть вкладку дёшево.

**Блокируем трекеры.** Страница тянет Google Analytics, Sentry, Facebook и ещё десяток сервисов. В облаке они закрыты, и страница могла бесконечно ждать их загрузки. Теперь Chrome отклоняет эти запросы сразу (`trackerHosts`), и страница открывается за 3–6 секунд вместо 20.

**Ждём подходы, а не загрузку страницы.** Страница собирается JavaScript-ом уже после загрузки, поэтому событие «загружено» ничего не гарантирует. Код каждые полсекунды читает `document.body.innerText` и ждёт, пока в нём появятся `кг x` или `повтор`.

**Язык задаём через JavaScript.** Hevy выбирает язык по `navigator.language`. Флаг Chrome `--lang` на macOS не работает, потому что Chrome берёт язык системы. Поэтому до загрузки страницы мы подменяем `navigator.language` на `ru-RU` (`languageScript`). Проверено в обе стороны: страница переключается и на английский, и обратно.

**Часовой пояс браслета.** Облако работает в UTC, и тренировка в 18:52 по Москве показывалась как 15:52. Chrome получает часовой пояс браслета, например `Etc/GMT-3`. Знак здесь перевёрнут по историческому соглашению: `Etc/GMT-3` значит UTC+3.

**Текст в формате заметок.** Страница даёт `1` / `80 кг x 12 повторений` отдельными строками, а `text.go` превращает это в `Сет 1: 80 kg x 12`. Буквы вместо номера подхода становятся метками: `F` → `[В отказ]`, `W` → `[Разминка]`, `D` → `[Дроп]`. Агент уже знает этот формат.

**Ничего лишнего.** Страница не открывается, если подходы в заметке уже есть (`HasSets`). Открываются только ссылки `hevy.com/workout/...` (`FindLink`), так что произвольный адрес из заметки Chrome не откроет.

## Прокси простыми словами

В облаке у программы нет прямого выхода в интернет: весь трафик идёт через прокси Anthropic. Это похоже на отладку iPhone через Charles Proxy.

**Проблема 1: Chrome не видел прокси.** Адрес прокси лежит в переменной окружения `HTTPS_PROXY`. `curl` и Go читают её сами, а Chrome нет. Это как `URLSession`, которому прокси нужно явно указать в `connectionProxyDictionary`. Из-за этого Chrome в облаке просто висел до таймаута. Теперь код читает `HTTPS_PROXY` и передаёт её Chrome флагом `--proxy-server`.

**Проблема 2: сертификаты.** Прокси может расшифровывать HTTPS и заново подписывать его своим сертификатом. В Charles то же самое: пока на iPhone не установлен и не помечен доверенным корневой сертификат Charles, приложения получают ошибку TLS. В облаке системе уже сказано доверять сертификату прокси. А у Chrome на Linux своё хранилище сертификатов, и про прокси он не знает.

**Как решили.** Простое решение — флаг «игнорировать все ошибки сертификатов». Но тогда Chrome примет и поддельный сертификат. Мы сделали аналог SSL pinning:

1. Go, который доверяет системе, открывает `hevy.com` через тот же прокси.
2. Из проверенной системой цепочки сертификатов берём отпечатки ключей (SHA-256 от SPKI).
3. Передаём их Chrome флагом `--ignore-certificate-errors-spki-list`. Chrome доверяет только этой цепочке, а все остальные сертификаты проверяет как обычно.

Если прокси трафик не расшифровывает, отпечатки просто не понадобятся.

## В чём была проблема и как починили

| Было | Почему | Стало |
| --- | --- | --- |
| Chrome в облаке висел до таймаута | не знал про прокси | прокси передаётся флагом |
| Страница ждала трекеры | домены трекеров закрыты в облаке | трекеры блокируются сразу |
| Полный Google Chrome не ставился (`xdg-utils`) | ставили его сами в setup script | Chrome уже есть в образе облака |
| Время по UTC, страница на английском | облако в США и в UTC | часовой пояс браслета и `navigator.language` |
| Внутренний API Hevy требует ключ | ключ закрыт | читаем публичную страницу |

## Ограничения

- Это не API: если Hevy поменяет вёрстку, разбор сломается. Тогда в `unavailable` появится `hevy`, а ссылка останется в заметке.
- Доверие сертификатам через отпечатки ещё не проверено в облаке. Если не сработает, в логе будет ошибка `ERR_CERT_...`.
- В облачном окружении должны быть открыты `hevy.com`, `api.hevyapp.com` и `d2l9nsnmtah87f.cloudfront.net`.
